## 1. 工具定位

本工具用于将上传图片作为生成约束，在保留人物身份特征或产品核心视觉特征的基础上，直接生成用户选择的目标风格图片。

本工具默认不输出提示词。内部完成参考图锁定、风格路由、导演设计和安全检查后，调用可用的图片编辑、参考图生成或多图合成能力。

这是工作流模块，不是内置图片编辑器。用户明确要求“只要提示词”时不调用图片工具；只收到参数或图片、未要求实际转换或编辑时，不自动生图。真实出图能力、输入图绑定、蒙版和尺寸控制都必须从宿主当前工具确认。

## 2. 与相邻能力的边界

| 用户目标 | 使用能力 |
| --- | --- |
| 分析图片、反推提示词 | `image-to-prompt` |
| 为同一人物写保真转换提示词，不出图 | 本工具的锁定流程 + `reference-image-lock`；仅返回约束提示词，说明文本无法单独保证保真 |
| 保留人物或产品，直接生成图片 | `reference-image-generate` |
| 上传服装并生成模特试穿图 | `reference-image-generate` 编排，`ecommerce-tryon` 主导服装还原 |

不得把本工具退化成普通文本生图，也不得在用户没有要求时先输出一大段提示词。

## 3. 触发条件

触发示例：

```text
保留我的五官，生成港风写真
用我的自拍做一张古风仙侠图
保持这个产品不变，生成一张高级广告图
保留我的脸，穿上第二张图里的衣服
把这个配饰戴到我的照片里
参考第一张图的人物，使用第二张图的产品，生成小红书种草图
不要提示词，直接出图
```

仅要求“分析图片”“反推提示词”“图片转提示词”时，改用 `image-to-prompt`。若同时要求保留原人物身份，须加载 `reference-image-lock`，不能套用“放弃人物身份”的纯风格反推模板。

## 5. 执行流程

```text
第一步：识别每张上传图片的角色；
第二步：确认人物图片属于本人或已授权成年人物；
第三步：建立人物 / 产品锁定表；
第四步：选定参考图模式、基准原图与修改白名单；
第五步：核对实际工具能力，然后选择唯一目标 Route 和可选 Overlay；
第六步：通过 director-gate 完成内部导演设计；
第七步：生成内部提示词和负面约束；
第八步：调用图片编辑、参考图生成或多图合成能力；
第九步：对照原图逐项检查视觉保真；严格保护区域另外验证像素；
第十步：必要时进行一次定向重试；
第十一步：返回图片和简短结果说明。
```

## 6. 图片角色识别

必须显式标注：

```text
identity_reference：本人或已授权成年人物图片
product_reference：服装、配饰、包装或普通实物
style_reference：只参考风格、构图、光线或氛围
edit_target：需要直接修改的原图
```

用户上传多张图但未说明用途时，先询问每张图片的角色，不自行猜测。

用户说“把这张照片转成某风格”时，原图是 `edit_target`，默认 `source_faithful_stylization`。风格图只供风格参考，不复制其中人物、发型、衣服、姿态或裁切。明确换装/换姿态/重拍时为 `identity_restage`，只解锁所点名的项目；“原图不变”“只改背景”“扩图保留原区域”使用 `protected_region_edit`，按核心规则记录保护区域和坐标。

## 7. 默认锁定策略

### 7.1 人物

完整锁定范围以 [../core/reference-image-lock.md](../core/reference-image-lock.md) 为唯一规则源。照片风格转换默认保护身份与五官、发型、服装配饰、身形动作、表情视线、人物数量、机位透视、构图与原裁切。只改变用户要求的表现方式，不用导演模板重新摆拍。

明确修改要求只解锁对应项目；没有“发型/服装/姿态默认可变”策略。年龄、民族、审美五官和新背景不能由默认参数或视觉库补入原人物。输入可见特征与 Route 负面词冲突时保护输入事实。

### 7.2 实际工具能力

- 提示词模式：生成可复制约束，能力验收止于文本，不能说原图已被编辑。
- 图片模式：把实际原图作为编辑输入或参考附件绑定到工具，按宿主接口记录图片对应关系。文本描述、文件名或链接不能替代实际图片输入；缺失必需输入时请求补充，不用相似人物补位。
- 默认照片转换优先使用原图编辑能力；只能参考图生成时，先说明无法保证几何保真，不能悄悄重建整个人物并宣称完成保真编辑。
- 严格保护区域必须有确定性遮罩/合成与逐像素比较路径。工具尺寸不支持原画幅时，不缩放或裁掉保护区域；采用保留原像素的画布方案，无法实现时说明限制并给方案。
- 按实际可用接口传原图、允许编辑区域、输出尺寸等参数；不捏造蒙版、身份锁权重、随机种子等不存在的控制项。遵循宿主工具自身的调用要求。

### 7.3 产品

默认锁定：

```text
品类；
轮廓；
颜色；
材质；
图案；
关键结构和装饰。
```

Logo 与小字尽量保留，但不承诺逐字准确。

## 8. 路由规则

```text
自拍 + 港风写真 → retro-hongkong
自拍 + 古风仙侠 → gufeng-xianxia 或用户明确指定的古风增强 Route
自拍 + 都市街拍 → urban-fashion
自拍 + 服装图 + 试穿 → ecommerce-tryon
自拍 + 配饰图 + 古风佩戴 → 目标古风 Route，配饰作为 product_reference 锁定
产品包装图 + 棚拍广告 → 选择最匹配的商业视觉方向，产品锁定优先
产品图 + 生活方式种草 → 目标生活方式 Route，产品锁定优先于氛围扩写
```

如果现有 Route 无法完整覆盖产品广告方向，仍可使用最接近的视觉 Route 作为导演参考；不得虚构未实现 Route。

## 9. 内部生成提示词要求

内部提示词必须明确写出：

```text
输入图片角色；
基准原图、参考图模式与原尺寸/原裁切；
必须保留的人物身份特征；
发型、衣着、动作、人数、机位、构图等锁定范围；
必须保留的产品核心视觉特征；
允许改变的内容；
禁止改变的内容；
目标 Route 和 Overlay；
原图模式复述可见场景、动作和镜头关系，仅在允许项目上应用风格；
重新拍摄模式也只为明确允许的项目设计新场景、动作或镜头；
严格区域编辑的蒙版、原图位置、输出尺寸与验证计划；
安全边界；
保真检查重点。
```

## 10. 保真检查与重试

首次生成后检查：

```text
人物脸型、眉眼、鼻唇是否明显漂移；
人物是否仍可识别；
发型、刘海/分缝/发际线与服装配饰是否变化；
身体和手部动作、表情视线与主体数量是否变化；
机位、透视、构图、主体占比、画幅与原裁切是否变化；
产品是否变成类似款；
产品颜色、轮廓、材质、图案或关键结构是否明显变化；
产品是否被手臂、头发、道具或构图遮挡；
目标风格是否覆盖了主体保真。
```

只描述实际可见、已对照检查的结果，不编造量化身份相似度。严格保护区域需报告保护像素数、差异像素数与坐标映射；未验证只能说明“尚未验证”，不能以目测“差不多”判定通过。

如果漂移明显，只允许进行一次定向重试：

```text
强化 identity_reference 的五官锁定；
强化 product_reference 的核心结构锁定；
从原始输入重做，只调整允许区域，不把漂移结果作为新身份基准；
降低不必要的风格化；
移除生成时擅自添加的动作和遮挡，保持原图本已有的复杂动作；
保留原目标 Route。
```

重试后仍无法满足时，明确说明限制，不静默切换为普通文本生图。

能力缺失无需先生成失败图。只有实际输入齐全且有可能纠正的保真失败才定向重试；重试范围服从用户任务授权与宿主资源限制，不无限尝试。

## 11. 安全与授权

允许：

```text
用户本人自拍；
已授权成年人物；
正常写真、换装、妆造和场景转换；
产品场景化；
服装试穿；
配饰佩戴；
广告图和种草图。
```

拒绝：

```text
未成年人或疑似未成年人物的性化转换；
未获授权的真实人物身份复刻；
明星、公众人物或第三方人物的欺骗性冒充；
偷拍、隐私侵犯、骚扰、诽谤；
色情深度伪造；
产品仿冒、虚假宣传或违法用途。
```

用户明确说“我的自拍”时视为本人授权。第三方人物图片授权不明确时，生成前询问确认。

## 12. 输出规则

默认输出：

```text
生成后的图片
简短说明：已保留的主体、应用的目标风格、是否进行了定向重试
```

说明区分“提示词已锁定”“视觉检查通过”“保护区域像素验证通过”。不能仅凭提示词要求声称已保留身份、发型、裁切或像素；若某项无法核实，要点明。用户只要提示词时，仅输出提示词和负面约束及必要能力说明，不要求用户先生成图片。

默认不输出内部提示词。用户明确要求查看时，才输出内部生成提示词和负面约束。

## 13. 最终原则

```text
参考图不是普通灵感图，而是生成约束；
照片转换默认锁定人物身份、外观、动作、数量、机位、构图与裁切；
明确修改只解锁对应项目，风格不能解除锁定；
原图不变需要确定性保护和像素验证；
产品参考锁定商品核心视觉；
Route 负责目标风格，不得覆盖锁定主体；
实际编辑请求返回图片，明确仅要提示词时尊重输出选择；
保真失败必须说明，不静默降级。
```
