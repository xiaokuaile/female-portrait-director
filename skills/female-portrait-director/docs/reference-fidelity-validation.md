# 参考图保真验证与安装回归

此文档提供可重复的验收方法。它不代表任何特定宿主或图像模型已经通过验收。保存测试记录时，分别列出以下三层结果，不把文件齐全或提示词正确写成图片编辑保真成功。

| 验收层 | 要证明的内容 | 必须保留的证据 | 不能由此推断 |
| --- | --- | --- | --- |
| 1. 安装与指令 | 模块可加载，输出模式和锁定规则正确 | 来源提交、安装布局、链接检查、测试输入与提示词输出 | 宿主已经连接图片工具或能编辑原图 |
| 2. 工具执行 | 宿主实际接收源图并执行所要求的生成或编辑 | 工具名称、支持的输入与遮罩能力、源图绑定、成功结果与输出文件 | 人脸、动作、裁切已保真，保护区像素未改变 |
| 3. 成图保真 | 所有锁定项满足要求；严格保护区域像素相同 | 原图与结果、锁定表、人工检查记录、保护区验证结果 | 换一个模型、尺寸、工具或任务仍会通过 |

## 安装与文件检查

在仓库或安装目录执行检查前，记录来源提交与本地修改。已有安装先备份，保留个人配置和作者的 `LICENSE`、`NOTICE.md`；不要以重新克隆覆盖已有目录。更新命令必须追踪预期的 fork，安装来源为原上游时不能假设更新会取得此 fork 的规则。

支持两种布局：

- 完整仓库：安装目录直接包含根 `SKILL.md`、`skill/`、`docs/`、`agents/` 和 `scripts/`。
- 独立分发：`skills/female-portrait-director/` 是安装器应复制的完整目录，内部相对引用不能依赖包外文件。

两种布局均须检查 `skill/core/reference-image-lock.md`、`skill/tools/reference-image-generate.md`、`docs/reference-fidelity-validation.md` 和 `scripts/verify_protected_region.py` 存在；`SKILL.md` 及 `agents/openai.yaml` 的版本与说明应一致。根源文件与包副本正文应一致；历史 BOM 和尾部空行差异可规范化比较，但不得忽略正文差异。查阅每个模块的 Markdown 链接与继承路径，确认在所选安装布局中均能解析。

### CLI 命令范围与安全更新

截至本次审查，[npm `skills` 发布包](https://www.npmjs.com/package/skills/v/1.7.2)为 `1.7.2`，要求 Node.js `>=22.20.0`。其发布源码提交为 [`671e8c320810d36fed80fac5f1a2c1bf7e82d812`](https://github.com/vercel-labs/skills/tree/671e8c320810d36fed80fac5f1a2c1bf7e82d812)。[官方更新说明](https://github.com/vercel-labs/skills/blob/671e8c320810d36fed80fac5f1a2c1bf7e82d812/README.md#skills-update)与[参数解析及更新实现](https://github.com/vercel-labs/skills/blob/671e8c320810d36fed80fac5f1a2c1bf7e82d812/src/update.ts)支持 `update [skills...]`、`-g`、`-p` 和 `-y`。

| 命令形式 | 精确作用 |
| --- | --- |
| `update female-portrait-director -g` | 仅选择同名技能，全局范围 |
| `update female-portrait-director -p` | 仅选择同名技能，当前项目范围 |
| `update female-portrait-director` | 同时检查项目与全局同名技能 |
| `update -g` 或 `update -p` | 更新该范围内全部追踪技能 |
| `update -y` | 省略范围询问，按当前目录是否存在项目技能自动选择范围；不是只更新本 Skill |

名称匹配不区分大小写。`update` 不支持 `--agent` 筛选，也不是只读预览；全局更新内部以非交互 `add` 重新安装技能，即使外层省略 `-y` 仍可能替换本地内容。项目本地路径安装不能自动按远端更新；需要从预期来源审查后重新复制。先备份本地修改，核对 `skills-lock.json`（项目）或 `.agents/.skill-lock.json` / XDG 状态目录中的安装来源（全局），再执行指定名称、指定范围的更新。手动 Git 克隆安装应使用其 Git 来源与本地合并流程，不假定由 CLI 追踪。

可在独立临时工作目录验证本地发行包，只用项目安装、不使用 `-g`：

```bash
npx skills@1.7.2 add /absolute/path/to/repo/skills/female-portrait-director --skill female-portrait-director --agent codex --copy -y
```

该版本的 Codex 项目目标为当前目录的 `.agents/skills/female-portrait-director/`，与手动安装到 `~/.codex/skills/` 的布局不同。比较复制结果与发行目录的文件集合和内容，确认所有保真模块、许可证、署名、验证脚本和测试随包复制；不要只检查 `SKILL.md`。隔离测试时禁用 CLI 遥测与 Node 编译缓存，将可能的 XDG 状态/缓存写入设为工作目录；无需改写 `HOME` 或 `CODEX_HOME`。这项复制测试只通过第 1 层，不证明宿主运行或实图效果。

安装后在新会话中只调用 `$female-portrait-director`，检查帮助中包含 20 种风格、提示词模板与图像能力条件。再运行以下提示词回归。安装器复制成功与帮助成功仅通过第 1 层。

## 提示词与路由回归

固定相同测试输入，并保存输出和图像工具调用记录。测试图像应是本人或已获授权的成年人物；可使用一张有明显发型、服装、手部动作、倾斜视角和边缘裁切的照片，以及一张两人合影。不要为测试加入与身份、动作或裁切无关的修改。

| 测试输入 | 预期模式与行为 |
| --- | --- |
| 旧的五字段模板，无参考图、无输出模式 | 继续返回标准提示词；不调用图像工具 |
| 上传照片：“转成港风，保持这张照片的脸、发型、衣服、动作和原始裁切，只要提示词” | `source_faithful_stylization`；锁定身份、五官、发型、服装、动作、数量、机位、构图、裁切；只输出提示词 |
| 上传照片：“做电影感风格转换，只要提示词”，不填新增字段 | 默认保真转换；Route 不新增人物、动作、服装或裁切；不出图 |
| 上传两人合影：“改成胶片质感” | 锁定两人的数量、各自身份、位置和遮挡关系；不默认改为单人写真 |
| “保留我的脸，只把上衣改成第二张图的衣服，其它不变，只要提示词” | `identity_restage`；仅服装项目可变，不能顺带改发型、动作、角度和裁切 |
| 自拍与风格图明确分工：“图 1 是原图，图 2 只参考色彩” | 图 1 锁身份与画面结构；图 2 不输入身份、发型、姿态或服装 |
| 多张图未说明用途，可能存在多种编辑目标 | 先询问图片角色，不自行选择人物或合成人数 |
| “向右扩图，原图区域完全不变” | `protected_region_edit`；记录原图宽高、输出宽高、整数偏移和可编辑范围；要求确定性保留与像素验证 |
| “原图完全不变，同时修改原图里的人脸” | 暂停冲突部分并澄清允许编辑的范围；不自动解除保护 |
| “参考图直接生成”，但宿主无图像输入或编辑能力 | 在生成前说明实际能力限制；不得以文本生图冒充参考图编辑 |
| 旧字段 `锁定强度：五官身份`，同时说“发型动作裁切不变” | 保留旧字段输入；更明确的保护要求仍有效，不能缩小锁定范围 |

检查锁定表与最终提示词逐项传播。保真转换中不能添加原图不存在的脸型重塑、发饰、服装、动作链、人物、机位或背景布局。风格描述应改变表现方式，保留画面已有事实。新增模式和字段均非必填，不能要求旧调用重填完整模板。

## 实图验收

先记录宿主是否支持源图输入、实际编辑、参考图生成、多图输入、遮罩、输出尺寸及无损导出。这些能力不能从“能生成图片”推断。工具调用必须把正确的 `edit_target` 和角色绑定传入，而不能只把人物文字描述送入文本生图。

对每个支持的模式保存一次完整测试记录：源图、角色与锁定表、明确允许的变化、内部提示词、工具输入、原始结果与最终交付文件。记录任何重试及其原因；通过结果只适用于此次记录的工具和设置。

对 `source_faithful_stylization`，在相同显示尺寸下并排检查原图和结果，再检查脸部、头发边界、服装图案、手部、画面边缘。逐项核对五官相对形状和可识别特征、分发和发长、衣领和服装结构、动作与目光、人物数量和对应身份、机位透视、主体位置、头顶与身体的原始裁切。允许风格处理的像素变化，因此全图像素不等不能单独判为失败；人工检查也不能证明严格原区域像素相等。不要输出未经实现的人脸相似度分数。

对 `identity_restage`，使用同一检查表，但只有用户明确允许的项目可以变化。不能把“身份可识别”作为其它锁定项全部通过的替代依据。

对 `protected_region_edit`，除视觉检查外必须执行以下像素验证。模糊比对、缩小预览、感知相似度或生成工具的成功状态都不能代替差异为零。

## 严格保护区域与像素验证

严格保护是一套确定性编辑流程：保留冻结的原图像素；用明确遮罩限定允许编辑区；生成后将受保护原像素原样回贴到输出；最终比较保护区域。回贴接缝的羽化、调色和修补也必须限制在允许编辑区。此 Skill 的只读验证脚本只检查结果，不执行生成、回贴或修复。

固定以下坐标与文件约定：

- 原图按需要先处理 EXIF 显示方向，再冻结为验证输入，明确记录此步骤。后续不得为使验证通过而临时旋转、缩放、调色、模糊或重新编码原图。
- 使用 PNG 等无损输出；原图与结果须采用相同解码模式，包括 alpha。ICC 色彩配置与 EXIF 方向须一致。JPEG 重新压缩不能保证像素完全不变。
- 可选允许编辑蒙版与原图同宽高，模式为 `L`，仅含 `0` 和 `255`：黑色 `0` 保护，白色 `255` 允许编辑。不要混用其它工具相反的蒙版语义；传给工具前显式转换并记录。
- 无蒙版表示全部原图像素受保护。扩图的 `--offset x y` 是原图左上角在输出中的整数位置；不是缩放、透视或亚像素映射。

验证环境需要 Python 和 Pillow。Pillow 仅用于本地解码比对，不是图像模型依赖；已有环境可直接使用。若缺少 Pillow，先为独立验证环境准备它。

同尺寸局部编辑，`allowed.png` 指定允许编辑区：

```bash
python3 scripts/verify_protected_region.py original.png result.png --mask allowed.png
```

原图完全不变，仅在右侧扩图，原图仍位于输出左上角：

```bash
python3 scripts/verify_protected_region.py original.png result.png --offset 0 0
```

在左侧新增 100 像素，原图在输出中向右平移 100 像素：

```bash
python3 scripts/verify_protected_region.py original.png result.png --offset 100 0
```

必须记录保护像素数量大于零且差异为零，尺寸、模式、色彩配置和方向检查均通过。验证失败则不能称“原图区域完全不变”。检查成功只证明所选保护区域的解码像素一致，不证明允许编辑区的人物身份、风格或视觉质量；蒙版若未保护完整原区域，也不能声称完整原图不变。

## 验证器回归与记录

用小尺寸 RGB 和 RGBA 无损样例检查验证器，分别构造：完全相同输入应通过；修改一个保护像素应失败；只修改白色允许区应通过；只改变保护区 alpha 应失败；明确整数偏移后完整保留原像素的扩图应通过。尺寸越界、模式不同、非二值蒙版、蒙版尺寸不同，以及 ICC 或 EXIF 方向不同均应失败。验证用样例不得作为真实照片保真已经通过的证据。

每次验收记录来源提交、安装目录与布局、宿主和工具版本、测试输入、源图尺寸、模式、允许变化、保护区域/蒙版、输出尺寸和偏移、结果文件、像素检查结论及人工检查结论。分开列出第 1、2、3 层的通过、失败或未覆盖项；缺失证据的项目保持未覆盖。
