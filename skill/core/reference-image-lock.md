## 1. 文档定位

本文件用于锁定上传图片中的人物身份特征和产品核心视觉特征。它不替代 Route、Overlay 或导演模式，而是在风格转换前声明哪些内容不得被扩写覆盖。

本文件必须被 `tools/reference-image-generate.md` 继承。服装试穿任务还必须继承 `routes/commercial/ecommerce-tryon.md`。

## 2. 图片角色

每张上传图片必须先标记一个角色：

| 角色 | 用途 | 默认锁定范围 |
| --- | --- | --- |
| `identity_reference` | 本人或已授权成年人物参考图 | 人物身份、面部比例和可识别五官特征；只开放明确要求修改的项目 |
| `product_reference` | 服装、配饰、包装或普通实物 | 品类、轮廓、颜色、材质、图案、关键结构 |
| `style_reference` | 仅参考风格、光线或氛围；明确允许时也可参考构图 | 不将其中的人物、发型、服装、姿态、人数或裁切迁移到已锁定原图 |
| `edit_target` | 需要直接修改或风格转换的原图 | 身份、面部、发型、服装配饰、动作、人数、镜头、构图及原始裁切 |

“把这张照片转成某种风格”足以确定该图为 `edit_target`，不要求用户再声明锁定项目。图片可以兼任身份参考，但要指定唯一几何基准原图。多图用途或基准图不明确且会影响结果时，先询问；已有明确说明时不重复确认。

在加载 Route、默认补全、参数推荐或五官库前选定模式：

| 参考图模式 | 适用请求 | 默认允许改变 |
| --- | --- | --- |
| `source_faithful_stylization` | 照片风格转换的默认模式 | 用户要求的色彩、笔触、材质表现、颗粒和光感；保持原有结构与明暗方向，不自动重新打光或换场景 |
| `identity_restage` | 明确要求换装、换发型、换姿态、换场景或重新拍摄 | 仅显式要求的项目；“古风”“电影感”等风格名本身不授权换装、换脸或重新摆拍 |
| `protected_region_edit` | 原图不变、只改背景、局部修饰、扩图且保护原区域 | 明确指定区域或新增画布；保护区域需要逐像素验证 |

明确换装等单项编辑也可继续以 `edit_target` 为基准；模式切换不会自动解除其它锁。参数未填写时从任务意图选择模式，不要求用户填新字段。

## 3. 锁定优先级

```text
安全边界
> 用户明确的保留要求和修改范围
> 模式默认保真锁定
> 用户选择的目标 Route
> Overlay
> Route 默认补全
```

Route 和 Overlay 只能修改未锁定内容，不得用默认五官、默认商品或默认造型覆盖参考图主体。

明确修改某一项只解锁该项，例如“换第二张图的外套”不解锁脸、发型、动作或裤子。保留与修改要求互相冲突时，仅澄清冲突项目；不得通过降低保真、重裁或重建人物偷偷解决。

## 4. 人物身份锁定

### 4.1 身份与照片保真

所有人物参考模式默认锁定：

```text
脸型与脸部比例；
眉形、眼型和眼距；
鼻型、唇形和嘴角特征；
可观察的稳定五官特征；
原有可见痣、疤痕、肤色特征和左右不对称；
原有年龄外观，不套用虚构生图的默认年龄或民族；
人物整体可识别度。
```

照片风格转换和未明确要求改变的原图编辑还默认锁定：

```text
发型轮廓、长度、卷曲度、分缝、刘海、发际线、发色和发饰；
原有服装与配饰的款式、颜色、图案、覆盖范围和可见结构；
身形比例、身体朝向、重心、四肢与手指动作、头部角度、表情和视线；
原有主体数量、人物对应关系、相对位置、遮挡顺序；
机位、拍摄角度、透视关系、景别、主体占比和构图；
背景物件及其位置，不添加剧情、道具或环境事件；
原始画幅比例、边界和已有裁切，包括被裁掉的头顶、手、下颌或身体；
未获授权的妆容、磨皮、瘦脸、眼鼻唇形、肤色或身形调整。
```

风格只改变表达方式，不凭风格模板补回画外内容、不将身体转向镜头、不添加/移除人物。超近真实面部 Route 的 60%–85% 脸部占比、完整额头/下颌，以及电影 Route 的负空间、动作或环境细节均服从原图锁定。Route/Overlay 的负面审美词也不能抹除人物真实特征。

“保持同一张脸”是高保真目标，不等于模型已证明同一身份。不要用自动人脸身份评分代替逐项视觉检查，也不根据照片推断姓名等身份信息。看不到的特征保持不可见，不编造。

### 4.2 授权判断

允许：

```text
用户明确说明是自己的自拍；
用户明确说明人物已经授权；
明确成年人物的正常写真、换装、妆造和场景转换。
```

必须先确认：

```text
上传第三方人物图片，但未说明授权；
人物年龄无法判断，且请求包含性感、纯欲、贴身穿搭或其他性化方向。
```

拒绝：

```text
未成年人性化；
未获授权的真实人物身份复刻；
明星、公众人物或第三方人物的欺骗性冒充；
偷拍、侵犯隐私、骚扰、诽谤；
色情深度伪造或非自愿情境。
```

### 4.3 原图区域严格保护

“原图不变”默认保护整个原图矩形；局部修改只解锁明确允许的区域。原图不变同时要求整图风格转换会互相冲突，须澄清是保留视觉结构还是保护原像素，不能把两者混为一谈。

执行前记录：原文件、原始宽高、输出宽高、原图在输出中的整数偏移 `(x, y)`、允许编辑的蒙版、保护区域、输出格式。蒙版坐标以原图为准，白色允许编辑、黑色保护；工具蒙版约定不同必须显式转换，不能反用。扩图应指定四边扩展量，不缩放、旋转、自动校正透视、重采样或重裁原图来适配工具支持的比例。

严格保护依赖确定性的遮罩编辑、原像素回贴或合成能力；生成式编辑器即使接收蒙版也可能修改蒙版外，提示词和肉眼均不能证明像素不变。按宿主可用工具及其要求生成允许区域，在不跨入保护区的情况下完成合成，再用无损输出比较保护区域。不能把生成结果整体替换原图。羽化、阴影、边界融合也须全部位于允许区域内。

比较解码后的像素（含 alpha），同时保持颜色模式、色彩配置与方向解释一致；保护区域差异像素必须为 0。整个文件的字节哈希可能因元数据或格式不同而变化，若用户要求文件本身不变则保留原文件另存编辑结果。不得用 JPEG 重编码、RGB 转换或有损压缩掩盖差异。

若没有确定性合成或验证能力，在调用付费/耗时生成前说明限制，提供可审查的蒙版/编辑方案或保真提示词；不声称“原图严格不变”，不静默降级为整图生成。验证脚本 [scripts/verify_protected_region.py](../../scripts/verify_protected_region.py) 是可选只读检查器，不提供编辑或生图能力。

## 5. 产品锁定

`product_reference` 默认采用核心视觉高保真：

```text
锁定品类；
锁定整体轮廓；
锁定主色和关键配色；
锁定材质；
锁定图案；
锁定关键结构和装饰；
避免产品被遮挡、裁切、变形或被 Route 默认物件替换。
```

Logo、包装文字和小字应尽量保留，但不承诺逐字准确。用户明确要求文字精确时，说明生成模型限制；必要时建议后续精确编辑或合成，不静默承诺。

产品图片默认按用户有权使用处理。不得用于仿冒、虚假宣传或违法用途。

## 6. 多图组合

支持：

```text
一张人物自拍 + 一张服装图；
一张人物自拍 + 一个或多个产品图；
人物图 + 产品图 + 风格参考图；
待编辑图片 + 补充产品图；
单独产品图 + 目标广告风格。
```

多图任务必须先形成内部图片角色表：

```text
图片 1：identity_reference
图片 2：product_reference
图片 3：style_reference
几何基准原图：
参考图模式：
原图尺寸、人数及可见身份特征：
目标 Route：
允许改变：
禁止改变：
保护区域、蒙版、输出尺寸和原图偏移（严格区域编辑时）：
```

## 7. 执行规则

```text
1. 识别每张图片角色；
2. 检查人物授权、成年边界和用途；
3. 选择模式，建立基准原图、允许改变与保护项目表；
4. 检查宿主实际的图片输入、编辑、蒙版、尺寸和合成能力；
5. 读取目标 Route 和可选 Overlay，只设计未锁定内容；
6. 按用户输出要求提供提示词或使用实际图片编辑能力；
7. 对照输入逐项检查脸、发型、衣着、动作、数量、机位、构图、裁切及商品主体；严格区域编辑另做像素验证；
8. 漂移明显时进行一次定向重试；
9. 仍无法满足时明确说明限制，不静默退化为普通文本生图。
```

## 8. 与其他工具的边界

- `image-to-prompt`：分析图片并输出提示词，不负责保留真实人物身份。
- `reference-image-generate`：编排宿主工具，接收原图约束；用户要求实际出图/转换/编辑时返回图片，明确只要提示词时只输出提示词。
- 本 Skill 是提示词与工作流说明，不附图片模型；“能加载模块”不证明能编辑图片或保真达标。
- `ecommerce-tryon`：服装试穿专项 Route，负责服装还原优先级。

## 9. 输出前检查

```text
- 图片角色是否明确？
- 人物是否为本人或已授权成年人物？
- 人物默认五官是否保持可识别？
- 原有痣、面部比例和发型细节是否漂移或被美化？
- 服装配饰、身形动作、表情视线和主体数量是否保持？
- 机位、透视、主体位置、构图与原始裁切是否保持，没有补出画外身体？
- 变化是否全部属于用户明确允许的范围？
- 严格区域保护是否比较过像素，并记录差异数量与坐标映射？
- 产品品类、轮廓、颜色、材质、图案和关键结构是否保留？
- Route 和 Overlay 是否只修改未锁定内容？
- 是否避免未成年人性化、欺骗性冒充和侵犯隐私用途？
- 是否避免对 Logo 和小字精确度作不真实承诺？
- 是否在保真失败时明确说明限制？
```
